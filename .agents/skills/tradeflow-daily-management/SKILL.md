# TradeFlow Daily Management

Read `references/daily-five-and-handoff.md`. Keep work moving through an accountable operating cadence, not an unbounded to-do generator.

## Daily five (provisional allocation)
1. **Product delivery:** highest-value dependency-ready app workflow, one verifiable increment.
2. **Master Intelligence:** narrowly bounded AI/data/voice behavior with negative and offline cases.
3. **Verification:** exact SHA CI, recovery/authorization check and truthful four-gate status.
4. **Customer learning:** owner outreach prep, real interview, evidence review or competitor workflow comparison.
5. **Commercial progress:** sales roleplay, offer/paid-pilot preparation, qualified-account verification or support-cost experiment.

Adjust allocation when a blocker or customer deadline materially changes value. No more than one active GitHub writer; research may proceed read-only. Each task needs owner, ready condition, result/artifact, value hypothesis, stop condition and dependency.

## Morning and weekly briefing
Daily output: yesterday's **actually verified** changes, one customer insight, today five tasks, risks/approvals, what the founder should do in sales and exact link/SHA. Weekly: kill weak hypotheses, rebalance based on evidence, update one authoritative ledger and handoff.

## Phone/offline reality
A recurring automation may deliver a scheduled briefing if separately created and authorized; it **does not automatically run GitHub coding or maintain a live computer**. Describe connected tools, actual automation IDs and permission limits. Never claim continuous execution without task logs/artifact evidence.

## Takeover
Write durable decisions, current remote SHA, actual CI, files, unfinished tasks, owner approval boundaries, research uncertainty, next invocation and a one-screen executive summary. Store in authoritative repository and appropriate Library/Drive folders where tools permit; do not overwrite owner research without versioning.
