# Daily Five and Handoff Cadence
## Daily briefing format
DATE/TIME ZONE | VERIFIED SOURCE SHA/PR/CI | ONE CUSTOMER INSIGHT (cite or UNKNOWN)
1 Product workflow — accountable owner, artifact path, proof requirement, priority.
2 Master Intelligence — bounded task, data/role dependency, required negative test.
3 Verification — latest SHA CI and browser/storage/auth status, real-device gaps.
4 Customer evidence — qualified buyer/source, next call or observation (not falsely claimed sent).
5 Commercial experiment — scenario practice, offer, support economics or pilot ask.
For each: state 'ready', 'blocked', 'proposed', 'in-progress observed' or 'verified'; owner and no-go conditions.
## Weekly meeting agenda
Review reality: verified shipped internal features, qualified owner interviews, refusal reasons, paid commitments, onboarding effort, cost to serve and newly revealed bottlenecks. Retire or resize work that does not serve the current ICP. Repeat the five highest-leverage tasks for next week.
## Founder attention allocation
Keep founder focused on real buyer interviews, sales roleplay, offer refinement, direct feedback and approvals. Engineering status belongs to principal engineer; manager simplifies rather than inventing tasks to keep founder busy.
## Automation caveat
Daily scheduled briefing/monitoring only after a real automation is explicitly configured and returns an ID. It can report changed GitHub status and planned work, but does not automatically grant unattended code-writing or deployment authority. A phone being on is not a production execution guarantee.
## Takeover checklist
Check same authorized GitHub PR and fresh SHA; reconcile pending and failed CI, reread ledger, open source artifacts. Do not duplicate completed features. Reverify buyer evidence files and source versions. Copy status, decisions, qualified assumptions and approval requests into linked Drive/Library handoff when connected. Give successor the next task with measurable finish line.
## Never say
'All done' without file evidence; 'team is working in background' without real run; 'customer validated' from fictional scenario; 'profit increase' from theoretical margin.
